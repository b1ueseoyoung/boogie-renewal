# 데모 흐름 화면, 새 디자인 방향 세 가지

화면을 쓰는 사람은 7~9세 아이와 옆에 앉은 보호자이고 문구는 한국어다. 사진 올리기(동의 안내 포함), 캐릭터 승인(원본 사진 옆 고른 후보, 후보 썸네일 3개, 버튼 3개), 이야기 진행(삽화, 글, 질문, 선택지 3개, 진행 2/5, 대기 상태, 오류 카드 2종), 읽기(펼친 책, 이전·다음 장, 읽어주기)의 네 화면을 세 방향으로 각각 그렸다. 사용자가 시안을 보고 하나를 고르면 할 일 37부터 그 방향으로 실제 화면을 바꾼다.

## 보는 방법

```sh
python3 -m http.server 8136 --bind 127.0.0.1 --directory docs/design
```

- 비교 페이지: http://127.0.0.1:8136/directions.html
- 시안: http://127.0.0.1:8136/mockups/a/ · http://127.0.0.1:8136/mockups/b/ · http://127.0.0.1:8136/mockups/c/
- 스크린샷(1280px, 390px 전체 화면과 360px·글자 150% 실패 시나리오): `.omo/evidence/task-36-kkumdokkaebi-v0-1-*.png`
- 대비 값 다시 계산: `python3 docs/design/contrast.py` (아래 "대비 값 스크립트 원문"과 같아야 한다)

## 세 방향에 공통인 규칙

- 빌드 단계 없는 순수 HTML과 CSS. 토큰은 `mockups/<방향>/tokens.css`의 CSS 변수이고 크기와 간격은 rem이다.
- 방향마다 바탕은 하나다(A, C 밝은 바탕, B 어두운 바탕). 운영체제 다크 모드 전환은 이번 범위가 아니다.
- 파란 강조색(개인 규칙)을 주요 버튼, 링크, 강조 글자, 포커스·선택 상태에 쓴다. 밝은 바탕 `#2f5bff`와 옅은 배경 `#e3e9ff`(버튼 글자 흰색), 어두운 바탕 `#7d9bff`와 옅은 배경 `#1e2a4d`(버튼 글자 `#0b0f1a`).
- 이야기 글은 1280px에서 20px 이상, 390px에서 18px 이상(`--text-story`는 clamp). 버튼과 선택지 높이는 44px 이상(`--tap`).
- 글꼴은 Google Fonts CDN과 대체 글꼴(Apple SD Gothic Neo, Malgun Gothic)을 함께 적는다. 사진과 삽화 자리는 CSS와 인라인 SVG로 그린 자리 그림이고, 글꼴 외의 외부 이미지나 스크립트는 없다.
- 문구는 실제 화면과 Contracts C-2의 문구다: 동의 안내(`CharacterCreationScreen.js`), "이 캐릭터로 할래요" / "다시 만들기 (2/3)" / "다른 인물로 바꿀래요."(할 일 26), "도깨비가 다음 장면을 그리고 있어요", timeout 문구와 "다시 시도", limit 문구, "이전 장으로" / "다음 장으로" / 읽어주기.
- 지금 화면(짙은 남색 바탕, 노란 강조색, 학교안심 나들이 글꼴)을 그대로 옮긴 방향은 없다.

## 방향 A — 종이 오리기

색종이를 오려 붙인 공작 시간. 각진 종이 조각을 겹쳐 붙이고 번지지 않는 오프셋 그림자로 화면을 쌓는다. 사진과 삽화는 살짝 돌아간 종이 틀에 마스킹테이프로 붙인다.

장점
- 굵은 테두리, Jua 제목, 밝은 바탕이라 7~9세가 세 방향 중 가장 쉽게 읽고, 원본 사진과 동화 속 모습을 나란히 비교하는 승인 화면이 가장 또렷하다.
- 단색 면과 테두리, 번지지 않는 그림자뿐이라 styled-components로 옮길 때 토큰을 그대로 쓸 수 있고 저사양 기기에서도 가볍다.
- 선택지와 버튼이 손에 잡히는 종이 조각처럼 보여 "누르는 것"이 분명하다.

걱정되는 점
- 요소가 많아 390px에서 네 화면을 이어 붙인 시안 페이지가 길다(전체 약 5,700px). 실제 화면에서는 한 화면씩 보이므로 덜하지만, 승인 화면은 세로 스크롤이 생긴다.
- 돌아간 틀(1.4도)이 사진 비교에 아주 작은 기울기를 준다. 적용할 때 0.5도 안팎으로 줄이거나 승인 화면에서는 세우는 쪽이 안전하다.
- 산호·연두 보조색이 생성 삽화의 색과 부딪힐 수 있다. 보조색은 하나로 줄여도 된다.

- 한 칸씩 세로로 쌓여 스크롤이 가장 길다(390px에서 시안 페이지 약 6,200px, 1280px에서도 약 5,300px). 어두운 화면은 데모 영상에서 압축 노이즈가 눈에 띈다.

- 테두리만 쓰고 글꼴도 하나라 구현과 유지가 가장 쉽고 글꼴 로딩 비용이 가장 작다.

- 글자 크기 단계가 작아 390px에서 이야기 글이 18px로 기준에 딱 맞는다. 적용할 때 한 단계 키워야 할 수 있다.
