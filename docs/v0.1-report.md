## 1. 무엇을 만들었나

캡스톤 때 만든 꿈도깨비(React 화면, Spring Boot + MySQL, FastAPI)를 구조는 그대로 두고 이 Mac 한 대에서 다시 돌게 만들었다. 실행 방법은 [`docs/RUN.md`](RUN.md)에 있다.

- 실행: `bash scripts/dev-up.sh` 한 번으로 MySQL 확인, FastAPI(8000), Spring(8080), React(3100)가 뜬다. 유료 API 키는 쓰지 않는다. 글과 그림은 ChatGPT 로그인 상태의 `codex exec`만 부른다. 실제 생성 없이 흐름을 확인하는 대역 모드(`--fake`)와 저장본만 재생하는 `DEMO_REPLAY`도 있다.
- 흐름: 사진을 올리면 기준 캐릭터 후보가 사진 옆에 나오고, 보호자가 승인하거나 다시 만든다. 승인본과 그때 만든 특징 문장(charLook)이 이후 모든 장면의 참조가 된다. 장르와 장소를 고르고 전개를 고르며 이야기와 삽화를 받은 뒤 읽기 화면과 책장에서 본다. 사용자, 캐릭터, 장면, 동화는 MySQL에 저장된다. 완성본은 진행 중에 만든 삽화를 그대로 쓴다.
- 실패 처리: 거절, 시간 초과, 한도 소진, 그림 없음 같은 실패 사유가 화면까지 전달되고, 화면은 사유와 다음 행동(다시 시도 등)을 보여 준다.
- 생성 방식: `GEN_METHOD`로 고른다. `gpt_char`(기본, 승인 캐릭터만 참조), `gpt_char_photo`(캐릭터 + 사진), `gpt_photo`(사진만), `baseline_repaired`(기존 ComfyUI 방식의 결함 수정본). 떠 있는 방식은 FastAPI `/health`의 `method`로 확인한다.
- 기록: 모든 생성이 `gen-log.jsonl`에 상태, 지연, 시도 횟수, 한도 수치(`used_percent` 전후, `resets_at`), 프롬프트와 참조 이미지 해시를 남긴다. ② 문서가 요구한 기록 항목(생성 시간, 실패와 재생성 횟수, 결과물당 비용)이 여기서 나온다.
- 비교 실험 도구: `python -m app.lab`(기준 캐릭터, 파일럿, 회차 실행, 매니페스트로 이어 하기), 블라인드 검토 화면 `/lab/review`, 리포트 `python -m app.lab.report`. 실험 규칙은 [`docs/experiment-protocol.md`](experiment-protocol.md)에 있다.
- 디자인: 할 일 36에서 시안 세 개(A 종이 오리기, B 밤 그림자 극장, C 알림장 노트)를 만들었다. 2026-10-03에는 응답이 없어 미리 정한 기본값인 시안 A로 진행했다. 2026-10-04에 사용자가 시안 C(알림장 노트)를 골랐고, 할 일 39가 데모 흐름 화면 전체에 C를 다시 입혔다. 방향 설명은 [`docs/design/direction.md`](design/direction.md)에 있다.

## 4. 재생성이 필요했던 경우

매니페스트 66건 중 시도 횟수가 2 이상이거나 상태가 `declined`, `timeout`, `no_image`인 작업은 0건이다. 그래서 목록이 비어 있고, 리포트의 "재생성 필요 목록"도 "없음"이다. 확인 명령:

```
python3 -c "import json;print(sum(1 for l in open('data/lab/manifest.jsonl') if (lambda m: m['attempts']>=2 or m['status'] in ('declined','timeout','no_image'))(json.loads(l))))"
```

같은 기준으로 gen-log도 봤다. 실험 구간(1~67행, 기준 캐릭터의 특징 문장 1건 포함)은 67건 모두 `ok`, 시도 1회다. 데모 실제 실행 구간(68~82행) 15건도 모두 `ok`, 시도 1회다. 98행의 `replay_miss`는 생성 실패가 아니다. 재생 모드에서 저장본이 없는 선택을 고르면 새로 만들지 않고 안내 문구를 보이도록 만든 동작이 그대로 기록된 것이다.

따라서 이번 기록만으로는 "기계적으로 재생성이 필요했던 경우"가 하나도 없다. 거절이나 시간 초과가 없었다는 사실까지가 이번 결과다. 그림이 나왔지만 책에 쓸 수 없는 경우(닮지 않음, 옷 바뀜 등)는 검토자의 "책에 쓸 수 있나" 답과 태그로만 드러나므로, 이 질문의 나머지 절반도 검토 대기다.

## 6. 데모 실행 기록

2026-10-05 01:28~01:43 KST에 실제 모드(`GEN_METHOD=gpt_char`, 상한 10포인트)로 한 편을 끝까지 만들었다. 사진 올리기, 첫 후보 승인, 장르 모험, 장소 바다, 매번 첫 번째 선택지로 진행해 동화 `261005EFNC`("바다의 심장", 6쪽)가 완성됐고 장면 6행이 DB에 저장됐다.

- 결과 15건(그림 7장 = 캐릭터 1 + 장면 6, 글 8건), 모두 `ok`, 시도 1회.
- 그림은 건당 36.4~49.7초(평균 41.0초), 글은 8.2~33.4초(평균 14.1초)였다(gen-log 68~82행). 브라우저에서 잰 가장 긴 대기는 마지막 장면(결말 글 + 전체 다듬기 + 그림)으로 약 82초였다.
- 한도: 주간 사용량 표시가 이 구간 앞뒤 모두 0.0%였다. 그래서 이번 실행에서는 건당 한도 소진량을 잴 수 없었다. 증가분을 0으로 적지 않고 "측정 불가"로 둔다.
- 저장본 재생(`DEMO_REPLAY=1`): 새 생성 없이 동작했다. 재생 구간 gen-log는 전부 `cached`였고 codex 호출은 0건이었다. 할 일 31의 재생에서는 그림 내용은 첫 동화와 같았지만(sha256 6/6 동일) 그림 주소가 요청마다 새로 만들어졌다. 할 일 40에서 캐시 적중이 처음 저장된 그림 주소를 그대로 돌려주도록 고쳤고, 고친 뒤 다시 재생한 동화 `261005SWWT`의 그림 주소 6개가 첫 동화 `261005EFNC`와 모두 같았다(6/6). 이 재생에서도 동화를 만든 gen-log 13행이 모두 `cached`였고 codex rollout 파일 수는 88개 그대로였다.
- 실제 모드에서 `scripts/dev-up.sh`가 Spring에 빈 `SPRING_DATASOURCE_URL`을 넘겨 Spring이 뜨지 않는 결함도 이 실행에서 드러났다. 이번 실행은 주소를 직접 넘겨 우회했다. 할 일 40에서 고쳐, 이 변수를 설정하지 않은 셸에서도 `GEN_METHOD=gpt_char DEMO_CAP_POINTS=10 bash scripts/dev-up.sh`가 exit 0으로 뜨고 `/health`가 `mode real`이다.

## 7. 한계

- 사진 1장: 결과는 한 사람, 한 장의 사진에 대한 것이다. 일반화하지 않는다.
- 성인 증명사진: 정면을 보는 성인 증명사진이다. 실제 사용자인 아이의 일상 사진과는 다르게 나올 수 있다.
- 화풍으로 방식이 드러난다: 기준선(toonyou)과 GPT Image는 그림체가 달라서, 과제 ID와 주소를 숨겨도 검토자가 기준선 그림인지 짐작할 수 있다. G1·G2·G3끼리는 같은 모델이라 이 문제가 작다.
- 시드 없는 재현성: GPT Image는 시드가 없고 같은 요청에도 결과가 달라진다(매니페스트의 GPT 행 `seed`는 모두 null). 재현성은 같은 그림을 다시 얻는다는 뜻이 아니라, 요청 해시, 참조 이미지 해시, thread_id, 결과물을 남겨 무엇을 어떻게 요청했는지 다시 확인할 수 있다는 뜻이다. 결과의 흔들림은 3회 반복으로만 본다.
- B0는 결정적: 시드가 고정이라 1회만 돌렸다. 반복에 따른 흔들림은 B1에서만 본다(리포트 경고와 같다).
- 한도로 중단된 구간: 없다. 실험과 데모 모두 한 번도 한도 규칙에 걸리지 않았다.
- 한도 측정이 사실상 비어 있다: 실험 시작 때 `used_percent`는 27.0(초기화 2026-10-06 11:50 KST 창)이었는데, 실험의 첫 호출 무렵 주간 창이 초기화돼 이후 모든 값이 0.0(초기화 2026-10-10 10:55 KST 창)으로 읽혔다(`plan.json`의 `windows`). 그래서 파일럿에서 잰 장당 소진량이 0이 되어 바닥값 0.2를 썼고, 그 결과 R이 3이 됐다. 실험 상한 40포인트 검사는 창이 바뀐 덕분에 통과했을 뿐, 상한 안에서 돌았다는 측정 근거는 아니다. 결과물당 비용은 이번 기록으로 말할 수 없다.
- 기록 밖 생성 1장: 할 일 25 실행 중 실행 스크립트를 넘겨받는 과정에서 경쟁이 생겨, 끊긴 실행의 codex 자식 프로세스가 혼자 끝까지 돌아 그림 1장을 더 만들었다(작업 `b10816f3`). 이 그림은 매니페스트와 gen-log에 없다. 파일은 `data/lab/jobs/b10816f3-7cda-4632-836c-b70e9adf4634/orphan-duplicate.png`로 옮겨 두었다. 그래서 실험의 실제 codex 호출은 48번(그림 47, 글 1)이고 기록된 것은 47번이다. 실험 결과가 틀린 건 아니고, 호출 수와 비용 집계가 1장 적게 잡혔다는 측정상의 주의점이다. 경위는 `.omo/evidence/task-25-kkumdokkaebi-v0-1.txt`에 있다.

## 8. 사람이 이어서 할 일

1. 3명 검토. 검토자는 서영과 동료 2명이다.
   - 실제 모드로 서버를 띄운다: `bash scripts/dev-up.sh`(대역 모드 `--fake`는 다른 데이터 폴더를 쓰므로 실험 그림이 안 보인다). 검토 화면만 쓰므로 새 생성은 일어나지 않는다.
   - `http://localhost:8000/lab/review`에서 이름을 넣고 과제 79개를 끝까지 평가한다. 이 Mac에서 한 명씩 차례로 하고 동시에 접속하지 않는다. 과제 순서는 이름을 시드로 섞이고, 비교군과 회차는 보이지 않는다.
   - 평가 항목: 닮음(사진 대 그림, 1~5), 일관성(한 회차 5장 묶음, 1~5), 책에 쓸 수 있나(예/아니오), 실패 태그. 척도는 [`docs/experiment-protocol.md`](experiment-protocol.md)의 "평가 척도"를 따른다.
   - 3명이 모두 끝나면 `cd backend-fastAPI && uv run python -m app.lab.report`로 리포트를 다시 만들고, 이 문서의 2절, 3절 표, 맨 위 결론 줄을 새 결과로 바꾼다. 결론은 리포트가 계산한 선정 결과만 옮긴다.
2. 통과한 방식이 정해지면 `GEN_METHOD`를 바꾼다. 비교군과 값의 대응은 G1 `gpt_photo`, G2 `gpt_char`, G3 `gpt_char_photo`, B1 `baseline_repaired`다(B0는 비교용이라 서비스 방식이 없다). `GEN_METHOD=<값> bash scripts/dev-up.sh`로 띄우고 `/health`의 `method`로 확인한다. 리포트가 "통과한 방식 없음"을 내면 기본값 `gpt_char`를 두고 조건별 미달 목록부터 본다.
3. 아이 사진으로 넓힐 때의 동의 절차(제안). 지금 프롬프트에는 "사진 속 사람이나 보호자가 동의했다"는 문장이 들어가므로, 실제 동의가 먼저 있어야 한다.
   - 보호자에게 서면으로 알리고 동의를 받는다: 사진이 Codex를 통해 OpenAI로 전송된다는 점, 요청 기록이 `~/.codex/sessions`와 `~/.codex/generated_images`에 남는다는 점, 사진과 결과는 이 Mac의 `data/`에만 둔다는 점, 검토자 3명이 그림을 본다는 점.
   - 동의 날짜와 범위(시연만, 실험 포함 여부)를 기록하고, 철회하면 `data/`의 해당 사진과 결과를 지운다.
   - ChatGPT 데이터 제어에서 "모델 학습에 사용"을 꺼 둔다. 아이 사진이 든 리포트나 스크린샷은 밖으로 공유하지 않는다.

## 9. 다음 단계 후보

- 추가 제어: 검토 결과에서 얼굴이 흔들리는 조건이 나오면 그 조건부터 손본다. 예를 들어 옆모습이 약하면 기준 캐릭터를 여러 각도로 만들어 참조로 넣고, 옷 바뀜에서 사람까지 달라지면 옷과 얼굴 참조를 나눠 주는 방식을 시험한다. 기준선 쪽은 자세 제어 같은 추가 제어를 붙여 볼 수 있다. 어느 쪽이든 검토 결과를 본 뒤에 고른다.
- 결과물당 비용 다시 재기: 이번에는 한도 창 초기화로 측정이 비었다. 같은 창 안에서 그림 몇 장을 만들어 증가분을 다시 재야 장당 비용을 말할 수 있다.
- 영상화: 동화 장면을 영상으로 만드는 일은 이번 범위 밖이다(영상 생성과 Seedance는 다루지 않았다). 그림 일관성이 검토로 확인된 다음의 후보로 둔다.
